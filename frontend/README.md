# Сторінка для ПР №2.17.3 — живе табло

Готова, нічого писати не потрібно. Її завдання — показати CORS на живому
запиті, а не навчити фронтенду.

## Запуск

```bash
cd frontend
python -m http.server 3000
```

Відкрити **http://localhost:3000** — саму адресу, а не файл.

## Дві заборони, без яких урок не відбудеться

**Не відкривайте `index.html` подвійним кліком.** Схема `file://` дає origin
`null`, і CORS поводиться інакше: ви побачите не ту помилку, яку вчите.

**Не піднімайте сторінку через Vite/CRA із `server.proxy`.** Проксі робить
запит на стороні dev-сервера, браузер бачить **same-origin**, і CORS не
виникає взагалі. Налаштування `CORS_ALLOWED_ORIGINS` у такому разі не
перевіряється — ви просто не дізнаєтесь, працює воно чи ні.

Якщо хочете підняти через Vite — дозволено, але **без** `proxy` і з портом
3000 (`vite --port 3000`), щоб адреса збігалася з `CORS_ALLOWED_ORIGINS`.

## Що робить кожна кнопка

| Кнопка | Запит | Що показує |
|---|---|---|
| Читати табло | `GET /scoreboard/` | простий запит — **preflight немає** |
| Додати гол | `POST .../events/` з JSON | `Content-Type: application/json` робить запит непростим → `OPTIONS` у Network |
| Прочитати X-Live-Count | `GET /scoreboard/` | заголовок видно лише з `CORS_EXPOSE_HEADERS` |
| Автооновлення | `GET` кожні 3 с | табло оновлюється живим |

Порівняйте перші дві на вкладці Network: один і той самий сервер, одна й та
сама сторінка — але `OPTIONS` з'являється лише перед другим запитом.

## Якщо немає інтернету

Сторінка тягне axios із CDN. Коли він не завантажився, той самий код
автоматично працює на вбудованому `fetch` — для CORS різниці немає жодної.
